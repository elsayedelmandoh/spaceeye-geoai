3. Debate on proposed solution (5-day Sentinel-2, 10,950 rows, >80% recall)
For (strongest arguments): (a) 5-day cadence captures faster physical change; (b) 10,950 rows increase the density of observations; (c) second-derivative (acceleration) is a standard time-series indicator; (d) teammate's observation of 0.0 boosting class_recall at time_test is real and deserves a documented response.
Against (verified, from repo): (a) Out of scope sec 1/89 rejects 5-day/monthly (noise > signal; quarterly accepted). (b) Arithmetic: 10,950 / (73 x 6 = 438 scenes per plot) is about 25 plots, not 12 compounds; no plot IDs or code mapping were shown. Consecutive 5-day scenes of one plot are strongly autocorrelated, so they are not 10,950 independent examples. (c) 2018-2023 data window ends before time-test 2025Q2-2026Q1 — no overlap, so it cannot improve that split. (d) Labels are synthetic (from the generator); more scenes don't make them independent real events (CURRENT_MODEL_METADATA.json limits 1-3; spec sec 3 item 5). (e) ">80% and more" is an unsupported accuracy claim — explicitly forbidden (spec sec 3 not-allowed list; sec 14 rules). (f) Threshold/min_samples_leaf change after seeing 0.0 violates sec 14 (no retuning after score; pre-register pass condition first; team_ideas.md). (g) D4 code freeze; ~6 days remain (sec 10 calendar). (h) Provenance/origin rule: new scenes need source, plot codes (not names), cloud-filtering proof, license, synthetic label 🟠. (i) Not a replacement for ACUD real data (data request list sec 12; K5 uses assumed rate; K6 uses published launch, not synthetic scenes). (j) Height/time-series claims must be labelled "estimate"; no new measured 2025/2026 heights (sec 1/4 out-of-scope row 79; adopted height context ends 2024).
Judge: "Against" wins. The teammate's observation (0.0 boosting class_recall, small n) is accurate; the remedy (a new out-of-scope 5-day source, unsupported recall promise, no overlap with test split) is the wrong mechanism. Valid response: clarify the metric confusion (class_recall vs recall_at_4) in reporting, keep current quarterly features (slope8/slope12/persist/tslc/d_* already exist), offer acceleration as a pre-registered candidate, and maintain the calendar/code freeze.
