4. Debate on R3 (short-window acceleration / 2nd difference)

Where she is right: slope8 = last 8 quarters (2 years), slope12 = 3 years — indeed long windows; a sharp 3-6 month slowdown before a full stall is captured late by slope8/slope12; the "acceleration" (2nd derivative / slope-of-slope) is the standard time-series complement.

Where the repo already covers it: K2 (kpis.py add_k2, line 144; spec sec 2) reacts in ONE quarter: count of consecutive quarters with A < threshold, starting ONLY after 4 active quarters; K2=1 → level 3, K2=2-3 → level 2, K2≥4 → level 1. A 3-6 month stall (1-2 quarters below threshold, after start) already moves priority up — that IS the short-window indicator. The teammate's proposed "sudden braking" is therefore a refinement of K2 or a second-difference feature on A, not a new missing concept.

Statistical limit (stated clearly): on quarterly, seasonal DW data, a 2nd-difference (acceleration) needs at least 3 consecutive points (≈9 months) to be defined; if computed quarter-to-quarter it must be year-over-year (spec sec 2: "every comparison is year over year; Dynamic World is seasonal") or computed from deseasonalised A, otherwise seasonal swings dominate acceleration. A monthly computation (teammate's 1,800-row series) conflicts with out-of-scope 89 (monthly rejected; quarterly only; see section 5). A causal (trailing-only) feature is required (no centered/centered rolling filter that uses future values — see section 6 finding about median).

Pre-registered candidate form (section 4 format): definition = (A(t) - A(t-4)) - (A(t-4) - A(t-8)) year-over-year (or slope12 difference on deseasonalised A), only for quarters with ≥3 quarterly points; owner R3 (teammate); pass condition written before any run (e.g. "if the new acceleration feature improves macro-F1_binary over baseline by ≥ X pp on the current time-test split with full denominator reported, and with no threshold change post-score"); log in team_ideas.md; D4 cut if not passed; never enters the level or X unless adopted; never advertised as a predictive-accuracy claim; origin mark 🔵 (derived from real observations; the labels stay 🟠 generated); always paired with its denominator and metric name in any report.

5. Debate on R5 (1,800-row monthly series; 2018-23 vs 2025-26; >80% claim)

(a) Monthly rows vs out-of-scope. Spec sec 1 out-of-scope 89: "Readings every 5 days — Noise above signal (monthly already failed); quarterly only"; sec 2: year-over-year, quarterly. A monthly feature-analysis dataset (1,800 rows = ~25 plots x 72 months at full coverage) is NOT a replacement for the quarterly model input; if proposed, it must be framed as an OPTIONAL feature-level analysis (not model training) with explicit plot-ID mapping and origin mark 🔵 for the derived scene features (labels stay 🟠 generated). It does not change X/level.

(b) Rolling Median: the reply does not specify trailing (causal) vs centered. Any rolling filter used as a feature at time t must be trailing; a centered median introduces look-ahead leakage into the feature and violates the "no leakage" rule (spec sec 3 item 6). The proposal must specify this explicitly before any run.

(c) Independence / arithmetic. The 96/48 compound-quarter rows (CURRENT_MODEL_METADATA.json) are the model's rows; the 10,950 scenes (teammate's proposal, not in repo) are scenes of plots, not of the 12 coded R7 compounds. 25 plot implication = 10,950 / (73 scenes/yr x 6yr ≈ 438 scenes/plot) ≈ 25 plots. Monthly observations of the same plot are highly autocorrelated (DW seasonal + construction-state persistence) — not independent real events. More rows do not make the 4-positive test larger; real independent events come from ACUD's real data (section 12 data request), not from scene repetition.

(d) 2018-2023 history vs 2025-2026 future / scenario argument. The teammate's phrase — "2018-2023 is the actual historical reality ... 2025-2026 is future scenarios; together they complete each other: history proves the model learned from real events, scenarios show it can simulate the future" — must be corrected: (1) the LABELS on 2018-23 are synthetic (generator stories aligned to real signals; CURRENT_MODEL_METADATA.json; DATASET_CONTRACT.md); saying "history proves the model learned" is partly true about satellite inputs but false about the label — the model learns synthetic labels, not real-world outcomes; (2) S1-S3 (spec sec 9) are what-if GENERATOR SCENARIO INPUTS (generated USD shock, collections drop, capacity change), NOT observations or model predictions — calling them "future simulation" of the model is a category error; (3) the approved wording (CLAUDE.md; spec sec 0; sec 5) is "hypothetical analysis" / "simulated hidden state" / "Synthetic - for training only" — never "simulates future" or "proves model learns". The teammate's phrasing must be rewritten to match the approved terminology.

(e) >80% retraction: FULL AGREEMENT. Confirm in debate text (see summary). No unsupported claim may appear in any file (spec sec 0 / 3 / 12; sec 14; current binary scope). Any number reported must carry method + split + view + denominator (n of m, capacity 4) + metric name (class_recall vs recall_at_4) + synthetic limit.
